## Delivered behavior

- **Truthful lint:** backend selector is `**/*.ts`. Unchanged rules now cover 84 TypeScript files, with zero errors/warnings. An intentionally unused variable supplied through stdin with a virtual TS filename fails with the expected `@typescript-eslint/no-unused-vars`; no probe source file was added.
- **One runtime:** `.nvmrc` selects Node **24.22.3 LTS**; `packageManager` selects npm **11.19.1**. Root engines accept >=24.22.3 <25 and >=11.19.1 <12; all four CI jobs select the same exact versions. A checksum-verified portable runtime was used for local checks without replacing the host installation. The lockfile changes only root engine metadata; dependency versions/integrities are unchanged from R12.
- **Working setup:** backend/frontend environment examples and two-terminal commands are documented. The root frontend script now forwards CLI options through nested npm correctly. Both actual development scripts started simultaneously against a disposable migrated demo DB, serving frontend, health and campaign reads successfully. Backend defaults to loopback; deployments must explicitly choose their listening host.
- **Verified restoration:** `/api/verify` preserves `isExpired:false` and adds a safe shared `AuthUser` from the current database account/role. Frontend restoration waits for server verification instead of trusting cached role JSON; focus, visibility, storage and Back restoration revalidate it. Initial restore fails closed if the API is unavailable. A transient recheck failure retains an active verified draft/session until expiry.
- **Session cleanup:** the JWT expiry timer clears identity, cancels queries and empties cache even while idle. Logout works offline. Generation/abort guards prevent late verification/login responses from resurrecting an old session. Existing R02 behavior remains: current-token protected 401 clears the session; 403, login credential failures and stale-token 401 retain the appropriate current session/status. Guest focus preserves public queries and a pending login. The client honors an explicit verification token even if storage changes during the request.
- **Safe errors:** an Express 4 async boundary routes rejected login work into the global error handler. Expected `HttpError` 4xx remain public; unknown/internal 500 errors, malformed JSON and oversized bodies return safe messages. Raw SQL, exception stacks, request bodies and credentials are not logged by that handler. Auth configuration failures also use it. Startup validates configuration, awaits asynchronous listen errors, closes an initialized DB on failure and exits 1 with a sanitized diagnostic.
- **Origin and login policy:** exact comma-separated HTTP(S) origins, required explicitly in production; arbitrary Origin requests receive 403 without CORS reflection. Origin-less callers retain existing route authorization. The app does not trust forwarded IP headers. A bounded process-local limiter defaults to 10 failed/in-flight login attempts per socket IP per 15 minutes; it reserves concurrent attempts, frees successful/server-error attempts, expires buckets and returns 429 with positive `Retry-After`. Credential schema bounds username length and bcrypt's 72-byte password boundary.

Runtime selection: [official Node 24 release artifacts/checksums](https://nodejs.org/download/release/latest-v24.x/) and [Node support schedule](https://nodejs.org/en/about/previous-releases). HTTP behavior follows [Express 4 API](https://expressjs.com/en/4x/api/) and [official CORS middleware documentation](https://expressjs.com/en/resources/middleware/cors/). CORS is a browser-origin policy; account authorization remains mandatory on protected routes.

## Limits and next task

R13 is complete locally; remote CI was not run because this branch was not pushed. Linux native installation remains for actual CI. The in-memory login budget resets at restart and is not shared across replicas; with `trust proxy:false`, a reverse proxy groups its users under that socket IP. Production needs an explicit trusted proxy topology plus shared edge/application throttling before scaling. Logout clears the client and does not revoke already-issued JWTs server-side; current account validity is still checked on every authenticated request.
