## CI and reproducibility

- Root `check:map` checks source **and deployed build** hashes, expected assets, polygon validity and provenance.
- Root `test:journeys` builds current output with an empty API origin for its isolated same-origin proxy. `-- --built` reuses an output already built in the same job, as CI does; it is not a stale-build validation claim.
- Pinned development-only `playwright@1.65.1` adds only Playwright/core to the locked dependency graph; no production dependency version changed. Chromium is installed explicitly with the matching CLI. No second test framework was added.
- The existing CI build job now runs map verification, compiled runtime/migration/seed smoke, the R11 disposable upgrade/backup/recovery rehearsal and migrated API/browser journeys after lint/typecheck/tests. It installs Chromium and Linux system libraries and has a 15-minute job limit.
- CI saves actual run results/screenshots via `actions/upload-artifact@v7` under the tested Git SHA. CI writes to a separate, untracked `output/playwright/r14-ci` directory, so an earlier committed successful result cannot be uploaded as evidence when the current job fails before the browser step.
- README now describes implemented features/stack, exact PowerShell setup/demo/two-terminal commands, build/check commands, actual screenshots, source-supported team contribution examples, separate data/artwork terms and remaining deployment dependencies. No root application license was invented.

Implementation references: [Playwright library launch API](https://playwright.dev/docs/api/class-browsertype), [matching browser/system-library installation](https://playwright.dev/docs/browsers), [CI guidance](https://playwright.dev/docs/ci), [official upload-artifact action usage](https://github.com/actions/upload-artifact). These explain configuration; they are not evidence of a remote run of this branch.
