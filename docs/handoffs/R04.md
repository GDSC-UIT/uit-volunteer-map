The route constants now include `API_ROUTES.TEAMS` and `API_ROUTES.LEADER.TEAM`. A Leader account with a different numeric Account ID and User ID resolves the correct team. Missing authentication is 401; current Admin requesting the Leader-only endpoint is 403; absent/inactive/unassigned profile or invalid team/campaign parent is 404. Existing R02 account validity checks still apply.

### Scope and ID semantics

- An omitted filter means all publicly readable records. Campaign/team filters require an existing readable parent; missing/deleted parent is 404. A known empty parent returns 200 with `[]`. Existing campaign/team filters that do not intersect return `[]`.
- Detail/filter IDs accept canonical positive decimal integers within Number.MAX_SAFE_INTEGER. Zero, negative/fractional values, exponent/hex forms, blank input, text, oversized IDs, arrays/duplicate parameters and nested query objects return 400. Numeric but nonexistent resources return 404. This parser is for reads; R03 mutation-ID behavior is unchanged.
- Public team/post queries exclude soft-deleted teams and detached campaign parents. Post queries also exclude deleted posts and detached teams. A campaign has no active/deleted flag, so campaign existence is used; historical campaign dates do not prohibit reads.
- Own-team derives identity from the authenticated actor; adding `?teamId=...&campaignId=...` cannot choose another team. Such parameters are ignored by that endpoint. The assignment rule matches R03 and TeamService; Team.leader/User.team lifecycle consistency remains R07.

## Transport DTOs and privacy

[Shared definitions](../../packages/shared/src/read-dtos.ts) are exported from the shared package. Backend [read mappers](../../packages/backend/src/transport/read.ts) construct explicit DTOs rather than returning TypeORM graphs.

- Campaign: IDs/name/dates, nullable description, ordered attachments.
- Team: teamId/campaignId, name, nullable description/imageUrl, active Leader summaries and ordered attachments. No full member/account graph. Leader summaries include only userId/fullName/avatarUrl and literal role `leader`; deleted profile/account entries are excluded.
- Post summary: identity, title/content/timestamps, `{teamId,teamName,campaignId}`, nullable public author summary and nullable thumbnail. List items intentionally omit the photos collection.
- Post detail: summary plus `photos: PhotoReadDto[]`. A missing/deleted author User is represented as null. Author summaries describe historical authorship and do not expose Account records.
- Photo: photoId, nullable title, URL, uploadedAt, **boolean** isFirstImage. Deleted photos are omitted. Existing first-image photos sort first, then photoId ascending; if several legacy photos are marked first, photoId is the deterministic tie-breaker. Thumbnail equals the first live photo, with lowest-ID fallback; no live photos means thumbnail null and photos `[]`.
- Attachment: attachmentId, URL, uploadedAt, nullable position. Sort by existing position first, null positions last, then attachmentId.

Nullable presentation fields are explicit nulls; collections are arrays. Passwords, emails, account IDs, role IDs, raw account entities and deletion flags are excluded from these read payloads. Regression tests assert exact payloads and absence of private keys. Photo ordering does not add a new position column or claim editable ordering; that migration/provider work remains R10.

Legacy shared entity/write-facing interfaces and frontend mock models are retained for existing consumers. R05 must import these new read DTOs instead of treating old entity interfaces or mock shapes as the live response. Do not send read DTOs wholesale as mutation payloads: R03 edit accepts title/content only and derives author on create.
