Repository search found `typeorm-model-generator` only in its manifest and release-plan discussion, with no import, command or configuration using it. Removing it removed **114 installed packages**, including its old ORM/driver/tooling subtree. The application keeps its existing TypeORM/SQLite architecture.

Affected compatible transitives/optional peers were also updated, including proxy-addr, form-data, follow-redirects, rollup, postcss, source-map-js, mysql2 and the typescript-eslint subtree. [Exact lockfile version changes](../../output/verification/r12/version-changes.json) and [resolved security packages](../../output/verification/r12/resolved-security-packages.json) are recorded. Existing React, React DOM, Leaflet and Tailwind versions were retained. No production endpoint, schema/migration, product layout, map data or persisted record was changed.

SQLite was the one direct major update. Installed TypeORM **0.3.31** declares `sqlite3: ^5.0.3 || ^6.0.0`; installed sqlite3 **6.0.1** requires Node >=20.17.0 and retains the backup API. The actual Windows x64 binding reports SQLite **3.52.0**. [Captured metadata](../../output/verification/r12/native-compatibility.json). The old installer tree's vulnerable tar/node-gyp stack was replaced; final tar is 7.5.23. The new optional node-gyp has a remaining inherited matcher finding discussed below.

Root engines/CONTRIBUTING now reflect the compatible Node ranges `^20.19.0 || ^22.12.0 || >=24.0.0`, covering the existing dev-tool floor as well as the native update. Validation here used **Node 24.11.1 / npm 11.6.2 on Windows**. Pinning one release/CI Node/npm version remains R13; the unchanged Node 20 GitHub workflow was not executed here.

Official release/reference context: [TypeORM 0.3.31](https://github.com/typeorm/typeorm/releases/tag/0.3.31), [sqlite3 6.0.1](https://github.com/TryGhost/node-sqlite3/releases/tag/v6.0.1). The sqlite3 upstream repository is archived; this update does not establish an active maintenance commitment. A future driver/ORM strategy needs a separate compatibility review.

## Audit result

Counts below are affected **package entries**, including inherited/meta vulnerabilities, not distinct exploitable application bugs. A full advisory list was preserved before changes and after the final clean install.

| Scope | Before total | Before critical/high/moderate/low | Final total | Final critical/high/moderate/low |
|---|---:|---|---:|---|
| Full tree | 51 | 6 / 28 / 13 / 4 | **16** | **0 / 13 / 3 / 0** |
| `--omit=dev` | 24 | 3 / 14 / 5 / 2 | **8** | **0 / 5 / 3 / 0** |

**Both final audit commands still exit 1.** Audit is not declared clean and no finding was suppressed. The 16 remaining package entries reduce to **three leaf advisories**:

| Advisory | Installed path / exposure | Disposition |
|---|---|---|
| [Picomatch repeated-extglob ReDoS](https://github.com/advisories/GHSA-fc5q-39xc-vjpf), high; no published patch observed | Vite/Vitest/typescript-eslint → tinyglobby/fdir → picomatch 4.0.7; also SQLite's optional node-gyp → tinyglobby/fdir. | No request-supplied matcher pattern exists in the current API. The compiled HTTP journey did not load picomatch, tinyglobby, fdir or node-gyp. Dev/test patterns come from checked-in configuration; node-gyp uses literal build/*.sln and build/*.mk patterns. Retain the finding and monitor upstream; do not infer global safety for arbitrary patterns or future code. |
| [Glob AbortSignal cancellation bypass](https://github.com/advisories/GHSA-3g3m-2fjr-6pw4), moderate; patch 14.0.2 | TypeORM 0.3.31 → glob 10.5.0. Loaded at migration discovery. | TypeORM calls glob.sync with the fixed migration-directory pattern, without AbortSignal options. Updating this parent to an unrelated major is outside the bounded update. |
| [Minimatch globparts amplification](https://github.com/advisories/GHSA-g3hv-75wg-m249), moderate; patch 11.0.1 | TypeORM → glob 10.5.0 → minimatch 9.0.9. | Patterns are the static trusted migration paths, not HTTP parameters. Keep the visible finding and reassess if that boundary changes. |

The primary picomatch advisory reports no patched release; downgrading Vitest/SQLite as suggested by some aggregate npm remediation hints would reintroduce other already-fixed findings. No forced fix, broad major override, package replacement/shim or custom vendor patch was used.

This is a scoped reachability assessment, not a blanket production security waiver. No externally controlled matcher input was identified in the current HTTP application. Production promotion must retain these input boundaries and consider the unpatched upstream finding. A service that later accepts user glob expressions, loads untrusted configuration or exposes development tooling requires fresh assessment.
