## Delivered scope

All existing post mutation routes now pass the authenticated actor to PostService: create, update, soft-delete and add-photo. The existing R02 middleware supplies the current Account/Role. Service checks resolve active User via `User.account.accId`, preserving the distinction between Account ID and User ID.

| Operation | Leader | Admin |
|---|---|---|
| Create post / initial photos | Active profile assigned to the selected active team. Author is that profile's UserId. | Any active team with an existing campaign; requires an active Admin User profile to derive author. Admin profile need not belong to that team. |
| Update / delete / add photo | Only posts in the active team currently assigned through User.team. An inactive/missing/unassigned profile is denied. | Any post with valid active team/campaign parents; an author profile is not required just to moderate an existing post. |
| Transfer team / replace author | Rejected in update payload. | Also rejected; ownership transfer is not an existing approved operation. |

The ownership rule follows the existing TeamService pattern: Account -> active User -> User.team. It deliberately does not use UserId = AccountId, a JWT-supplied author, previous post authorship, or the Team.leader relation as an alternative authorization path. Coherence between Team.leader and User.team remains the R07 assignment task.

Active team means `Team.isDeleted = 0` with an existing Campaign relation. Campaign currently has no active/soft-delete field; no new status, date-window or historical-post policy was invented. Deleted post/team and missing/detached parents reject mutations before Post/Photo writes. Public reads remain unchanged for R04 to address separately.

## Request contract

Create payload: `{title, content, teamId, photos?}`. The server derives author; callers must stop sending authorId. Team ID is a positive safe integer. Each photo accepts only `{title?, imageUrl, isFirstImage?}`; image URL must be valid and the optional first-image flag remains 0/1 (or null).

Update payload: `{title?, content?}`. Strict schemas reject authorId, teamId, nested relation objects and unrelated ownership fields with **400**, including attempts to resend an unchanged teamId. The photo endpoint also rejects client-supplied post/team relation fields. Existing successful write status/envelope remains 200. Actor is not part of the request body.

- **401**: authentication missing/invalid/deactivated (R02).
- **403**: authenticated Leader cannot access the target team, or no active profile exists to create an author.
- **404**: post deleted/missing/detached, team deleted/missing, or campaign relation absent.
- **400**: invalid mutation post IDs or invalid/forbidden body fields.

Mutation ID validation is centralized in the checked-post service path; it rejects nonpositive, fractional, nonfinite and unsafe numeric IDs. Existing public read/filter/ID contracts are not redesigned here.
